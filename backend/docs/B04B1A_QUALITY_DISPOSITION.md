# B04B-1A — persisted quality disposition

Historical milestone: completion, shipping and deployment limitations below are not the current application contract. See [current quality API contract](QUALITY_API_CONTRACT.md).

This isolated development capability records partial authorized classification of reconciled B04A good/pending production output. Migration 008 adds append-only, tenant/site RLS-protected records with a composite foreign key to the exact output ledger row, production event, input lot and work order. PostgreSQL runtime obtains SELECT, and INSERT only in isolated development; UPDATE and DELETE are denied. Readiness checks RLS and restricted role and, in isolated development, required INSERT and absence of UPDATE/DELETE. The app checks `quality.write` within the idempotent transaction, locks the parent order shared with B04A production, validates physical input reconciliation, checks the remaining event quantity and writes audit and disposition atomically. The API accepts an explicit actor-supplied evidence reference; it does not verify evidence documents or fabricate drawing approval.

A quality decision is classification only. It does not create a new lot, physical stock, release, reservation or receipt. Existing B04A completion semantics still use historical pending totals and thus can block completion even after all pending output is classified. This is deliberately unchanged in B04B-1A and requires B04B-1B reconciliation work. Downstream operations, rework execution, assignment, drawing acknowledgement and shipping remain unsupported.

The trusted application process supplies transaction context; as documented in B03A, RLS does not protect against a compromised runtime process able to execute arbitrary SQL or forge context. Live OIDC interoperability, production authentication, separate migration/runtime role provisioning, deployment hardening and production authorization remain open. This feature is disabled outside isolated development.

## Verification

PostgreSQL 16 with real restricted runtime roles: **86/86 tests passed, zero failed or skipped**. [TAP](evidence/b04b1a-postgresql16.tap). The quality integration test includes 20 pending units classified 12 approved/3 rejected/5 rework, over-disposition and concurrency rejection, stable idempotency replay, a quality inspector, operator denial, cross-tenant and cross-site denial, incorrect lot/event, missing evidence, disabled reservation route, drawing fail-closed, append-only history, readiness grant revocation and audit failure rollback. Migration tests cover 001/002 → 008, failed 009 rollback, and a fictional backup/restore. Four subtests plus the enclosing quality integration test account for 5 tests; the existing B04B projection has 5 tests.

The [isolated Docker Compose smoke](evidence/b04b1a-compose-smoke.txt) rebuilt the final API source, ran migrations and provisioning, checked readiness, and rejected unauthenticated session and quality requests. A live OIDC provider was not exercised. The initial immutable-history test expected SQLSTATE P0001 but the existing trigger correctly returned 55000; the test expectation was corrected and the complete suite rerun.
