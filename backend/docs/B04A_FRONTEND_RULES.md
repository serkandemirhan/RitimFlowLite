# B04A — frontend production rules

Frontend analysis only; no localStorage data is changed. `ux-operator.js` requires a machine, authorized owner or manager, current drawing revision acknowledgement, physical unprocessed input and no handover before starting; pause requires a running job; resume requires paused state, machine, drawing acknowledgement and no handover. `workforce-service.js` separates operator assignment and explicit take-over, and prevents changing the owner of a running job without first pausing. Quantity recording requires a running job, authorization, drawing acknowledgement and a positive integer not exceeding physically unprocessed input. Direct `good` requires manager or an explicitly authorized self-inspection policy; other outputs are QC-pending, scrap and setup scrap. `transfer-service.js` consumes specific lots and preserves historical production separately. Closing requires no unstarted, unprocessed, pending or rework quantities.

B04A has no backend assignment, drawing acknowledgement, inspection, rework, handover or self-inspection policy commands. The development workflow accepts only a verified assigned operator with exactly one active machine/operator assignment. If drawing revisions exist, operations fail closed until acknowledgement support is implemented. Self-classified good output is restricted to an assigned operator who also has a manager-equivalent grant; other operators may record pending or scrap. Output is not final quality release or downstream-ready stock. Setup scrap is supported as a separate outcome. QC-pending jobs cannot close until a future quality decision flow reconciles them; existing legacy production without matching lot consumption is not normalized.
