# Drawing revision acknowledgement — isolated development

Baseline `40e3e201e98abbd7d71edbe24515e8792f154bae`. Migration 014 adds immutable, tenant/site-scoped document, publication and actor/work-order acknowledgement records, audit references, forced RLS and restricted runtime grants/readiness. Historical revisions are not silently selected or migrated: without an explicit publication they block production. The manager publication command stores the fictional PDF bytes and its SHA-256; document reads and the production guard verify the digest. Explicit acknowledgement binds the authenticated, currently assigned operator to the exact publication and revision. A new publication invalidates earlier acknowledgement; no PDF open action acknowledges it. The same order lock serializes publication, acknowledgement and production. Pause remains available as a safe stop after a drawing change. API contract and limitations are documented in API_CONTRACT.md.

Real PostgreSQL 16 restricted-runtime `npm test`: 101/101 passed, including drawing publication, revision change, old/other-operator rejection, document integrity, membership revocation, cross-tenant/site rejection, idempotency and audit rollback. Fixture setup and migration use privileged/separate owner roles; application requests use the restricted runtime role. Database/backup tests used an isolated fictional database and PostgreSQL 16 client tools. Compose 014 readiness returned 200 and unauthenticated drawing discovery returned 401. See the corresponding frontend integration report for end-to-end browser evidence.

The upload accepts a bounded PDF envelope and stores bytes in PostgreSQL solely in isolated development. It does not implement production-grade PDF inspection, malware scanning, durable object storage, a document management system or a real identity provider. Operators explicitly attest review; the application cannot establish that they understood the document. RLS does not defend against arbitrary SQL by a compromised runtime process. Existing historic records remain intact and fail closed until a new explicit publication is made. No deployment or production write activation is authorized.
