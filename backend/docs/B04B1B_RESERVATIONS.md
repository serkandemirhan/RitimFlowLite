# B04B-1B persistent reservations and downstream planning

Migration 010 adds immutable `output_reservation_events`, with global identity sequence, tenant/site forced RLS, event type, source output lot/event/work order, destination work order/operation, actor and a foreign key to the actor-scoped persistent idempotency command. A release references the original reservation with the same provenance via a composite self-FK. Exact sequence numbers may have gaps; the common parent-order row lock serializes all production, classification, reservation and release transactions for one order. Under this lock the service reads persisted events in sequence and verifies approved availability, source reconciliation, destination capacity and operation order. RLS and composite FKs are defense in depth; the documented compromised-runtime context limitation remains.

`downstream-work-orders` atomically creates a waiting first adjacent internal-operation work order and its reservation. `output-reservations` attaches approved output to an existing eligible waiting destination. Releases append history and can make approved planning quantity available again. The quality classification and output genealogy are unchanged; historical events without output lot identity cannot be used. A release is not a physical movement, and B03C transfer and B04A downstream execution remain disabled. Returned quantities are planning balances, not physical stock.

B04B-1C remains open: completion reconciliation against resolved quality, unsupported rework lifecycle, secure assignment/handover and drawing acknowledgement. A future physical-flow phase must separately design shipment/receipt provenance; no server-authoritative availability here implies physical receipt. Development APIs are disabled outside isolated development, and actor-supplied inspection evidence is not independently verified. Real OIDC, multi-user production activation and the compromised runtime threat need separate review.
