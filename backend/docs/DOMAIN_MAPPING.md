# Existing browser domain → server mapping

Source baseline is candidate `3675b270c322a89dc32e7422a5c457cbbfe29f52`; the separate UI branch may have later uncommitted changes. Existing rules remain the reference and must be reused or checked by differential tests, not silently replaced. B01 has no MES mutation endpoint; SQL constraints are only a first layer.

| Domain | Existing source and behavior to preserve | B01 storage; remaining server work |
|---|---|---|
| Orders and routes | `quantity-model.js` `route`, `operationProof`, `orderQuantities`: route support, exact ordered quantity, cumulative history vs physical location, net customer shipments | `orders`, `operations`; implement route versioning, transition rules and read models. Current model supports terminal external operation; internal→external→internal needs a separately designed extension. |
| Work orders/planning | `planning-service.js`: manager only, planned capacity, prior qualified good, reduce/release and reserve/send/accept, no excess | `work_orders`, `reservations`, `work_assignments`; lock order/operation and input lots before checking aggregate capacity, implement event history, authorization and atomic order + first job. |
| Assignments | `workforce-service.js`: manager assigns, explicit operator takeover, machine release with reason, running and ownership checks | `machines`, `work_assignments`; active machine uniqueness is a DB index; implement actor/membership and state transitions. |
| Material | `stock-service.js` receive/authorize, conversions and allocation caps; UI legacy paths must not bypass shared command | `material_receipts`, `reservations`, `lots`, `stock_movements`; validate source unit and conversion separately, document duplicate semantics, lock capacity and stock. |
| Transfers | `transfer-ledger.js` provenance and balances; `transfer-service.js` issue/accept/reverse/consume, reject duplicate accepts and nonexistent lots | `physical_transfers`, `transfer_events`, `lots`, `stock_movements`; retain provenance and transactional state machine; exactly-once acceptance. |
| Production | `quantity-model.js`, `ux-operator.js` UX-05: 60 good/3 scrap/12 pending/25 unprocessed, 25 physical vs 50 unstarted planned, setup scrap and handover | `production_events`, `stock_movements`; server equivalents, ownership, lot consumption and lock/revalidation must be implemented. Preserve historical cumulative good separately. |
| Inspection/rework | `quality-service.js` policy, self-inspection grant/revocation, case→task→execution→result→reinspection and origin lineage | `quality_decisions`, `rework_tasks`; additional policy, execution and result tables needed, provenance enforced per command. Historical missing evidence is a warning, not fabricated data. |
| External | `shipment-service.js` dispatch, `stock-service.js` supplierReturn/supplierRework: partial good/scrap/rework/loss reconciliation and supplier context | `external_dispatches`, `external_returns`; enforce aggregate returned ≤ dispatched and route-specific release inside transaction. |
| Final release/shipment | `shipment-service.js` release/ship and `quantity-model.js`: final operation completion + final QA before customer shipment; only approved ready inventory; net shipment drives completion | `quality_decisions`, `shipments`, `stock_movements`; SQL references alone do not prove eligibility, type or balance. Row locks and full rules are mandatory. |
| Customer returns | `stock-service.js`: shipment-linked cases, quarantine, disposition, controlled restock/rework and reasoned reverse | `customer_returns`, `quality_decisions`, `stock_movements`; add dispositions and reverse provenance; enforce aggregate per shipment. |
| Compensation | `stock-service.js` compensate: bounded by documented loss; additional first operation/material limit does not increase customer demand | `compensations`; compute eligible source quantities and concurrent usage transactionally. |
| Drawings | `drawing-service.js`: reasoned revision, prior file retained and job/operator acknowledgment | `drawing_revisions`; implement acknowledgments, object storage and access control; never invent old revision provenance. |
| Integrity | `integrity.js` pure structured findings and affected-order guard; P0-06 legacy exceptions distinguish absent historical proof vs invalid references | implement DB read-only audit and server command gates, test old data compatibility explicitly. |
| Persistence/concurrency | `persistence.js` schema/recovery; `transactions.js` Web Locks, revision, durable command fingerprint. P0-07/08 only protect local demo | PostgreSQL transaction + idempotency foundation; real auth, DB locking, durable history and tested recovery/backup still required. Never automatically import browser localStorage. |

`tests/p0-*.test.cjs`, `tests/p1-domain.test.cjs` and browser fixture scenarios are the behavioral contract. Preserve UX-05, UX-06 and all existing P0/P1 negative cases in server differential/concurrency tests. Legacy no-provenance exceptions require a documented import process in a later phase, not silent conversion.
