# UX Sprint 2 — implementation and verification

Baseline: `integration/i01-frontend-backend` commit `a9fc897343cb024efb90b91a1607f330c1fb4d30`; branch `frontend/ux-sprint-2`. Sprint 2 closure baseline. No deployment, push or user data reset.

The operator screen places the state-specific action before the quantity breakdown, with transfer, receipt, inspection and handover grouped as secondary operations. Assignment and drawing acknowledgement follow the main operator workspace. Existing mutation services and validation remain authoritative. Pending and completed quality views are separated from rework; policy controls are disabled for non-managers. Inspection records do not record the historical drawing revision, so the UI explicitly reports it unavailable rather than claiming the current revision was used.

API development mode remains the I02 Orders/Planning subset. Production, quality, rework, transfers and shipment mutations remain unsupported; API errors do not fall back to demo storage. OIDC provider integration is not live. Screenshot comparisons use isolated fictional fixtures and are available in this directory at 390 and 1440 pixels; browser viewport simulation is not real-device acceptance.

With Node 22 and macOS Chrome, `npm run test:ci` passed: 292 domain tests, 12 packaging tests, one 41-asset smoke, 110 source and 110 packaged browser checks, and 32 source plus 32 packaged isolation/Sprint 0/1 checks. See [CI log](evidence/ci.log). New Sprint 2 checks passed 7 responsive and 4 work-order state scenarios on each of [source](evidence/sprint2-source.log) and [package](evidence/sprint2-package.log). I02 real Fastify/PostgreSQL 16 premium scenarios passed 1/1 on each of [source](evidence/i02-source.tap) and [package](evidence/i02-package.tap); signed fictional tokens and a simulated JWKS were used. I02 unit regressions passed 15/15; two-session overplanning passed 1/1 before the final operator-only placement adjustment.

Limits: The new state tests verify at least 44px height for primary operator actions on source and package; 44px minimum styling also applies to quality list cards. Not every secondary touch target was measured. Existing Sprint 0 tests cover modal focus/Escape and keyboard viewport behavior and P1 tests cover drawing access, but the new Sprint 2 suite does not independently test a real mobile keyboard or physical device. Prior Linux GitHub Actions PDF ERR_ABORTED remains unresolved on that platform; this is a local macOS run and no request failures were globally suppressed. No real OIDC, multi-device backend production authorization, or deployment acceptance is claimed. Historical drawing revision cannot be reconstructed from existing inspection records.

## Closure verification

The closure run using Node 22 and macOS Chrome completed with 292/292 domain, 12/12 packaging, 1/1 smoke, 110/110 source and 110/110 packaged browser tests, plus 32/32 isolation and Sprint 0/1 checks for each target. [Complete retry log](evidence/closure-ci-retry.log). Sprint 2 checks passed 11/11 on each of [source](evidence/closure-ux-source.log) and [package](evidence/closure-ux-package.log). Real Fastify/PostgreSQL 16 I02 tests passed 1/1 [source](evidence/closure-i02-source.tap), 1/1 [package](evidence/closure-i02-package.tap), and 1/1 [two-session race](evidence/closure-i01-race.tap); command units passed 15/15.

The first closure CI attempt ran alongside two browser suites and failed B02 at 1440px while waiting seven seconds for the production button to become stable. No application errors were reported. The same case and full suite passed when run alone; resource contention is plausible but not proven. The [first log](evidence/closure-ci-initial.log) and [failure detail](evidence/closure-ci-initial-p0.json) are retained.

Acceptance blockers remain: physical iPhone Safari and Android testing; a new Linux GitHub Actions PDF `ERR_ABORTED` verification; unsupported Production/Quality API mutations; and live OIDC authentication.
