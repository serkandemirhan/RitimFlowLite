# I01 — development integration draft

Baseline `74718e4038249e37fc10e7b871f95d80f3dca532` on separate branch/worktree. Sprint 0/1 uncommitted frontend diff and three browser tests copied from the existing frontend worktree without modifying it. The integration screen lives at `/integration/` and runs with `node integration/dev-server.cjs`; it binds only 127.0.0.1 and proxies `/api/v1/` only to 127.0.0.1:3000 (or I01_API_PORT). Use only an isolated fictional database with backend isolatedDevelopment enabled. The existing localStorage demo is neither read nor used as fallback. Access tokens are held in memory; the screen accepts a real short-lived bearer token but does not implement OIDC login or provide one.

Adapter requests server session, memberships and scoped capabilities before listing or mutating orders. It supports first operation planning only. Permissions disable the corresponding forms; server checks remain authoritative. POST commands use idempotency keys and retain a key for an unresolved network/server error while the page remains open. Pending retry keys are not persisted across reload; interrupted writes across reload require further work before reliable adoption. Unsupported operations are labelled; no backend production endpoints are exposed in the UI. The proxy is development-only and is not a production gateway.
