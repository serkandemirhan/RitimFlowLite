# OIDC final security closure

**Historical record:** the Chrome trust blocker described below was subsequently resolved and the real Chrome/Keycloak/Compose tests passed. The current cross-worktree acceptance record is `backend/docs/oidc/CHROME_TLS_ACCEPTANCE.md` in the backend worktree.

Current decision: **development NO-GO; production NO-GO**. This report supersedes the prior owner-assisted legacy migration plan. Existing server-encrypted pending commands and PostgreSQL history remain intact.

On API initialization, the frontend enumerates sessionStorage and localStorage keys and removes the old plaintext `ritim:api-dev:pending-commands:v1`, `ritim:api-dev:order-workflow:v1` and scoped workflow variants without parsing, displaying, replaying, or migrating their contents. It verifies removal and fails closed on storage access/removal failure. The same check runs before selecting a site and account transitions; the separate API developer page also cleans before use. Old uncommitted drafts are irreversibly abandoned; already committed server transactions and audit/idempotency history are not deleted. Cleanup concerns the currently accessible browser storage and cannot retroactively prevent past disclosure, reach another tab's sessionStorage, or control still-open older application code. New recovery is still encrypted on the server, scoped to verified identity and reuses the original idempotency key.

A real Keycloak/Fastify/PostgreSQL 16 browser test passed, including cleanup before resumed authenticated use, same-tab account change, cross-actor recovery denial, lost response and server restart. Backend restricted-runtime regression passed 125/125; recovery frontend unit tests passed 12/12. The first CI attempt failed package smoke because two unused legacy modules were removed from HTML but remained in the asset manifest; the manifest was corrected and the failed log is retained. Report final CI separately.

The corrected full CI passed: 292 domain, 12 recovery, 12 packaging, 110 source browser, 110 package browser, and 32 source plus 32 package isolation/Sprint checks. The generated artifact contained 43 assets and smoke loaded all of them with no unexpected application errors. Against real Fastify/PostgreSQL, source and package I02, production/quality and two-operation scenarios each passed; Sprint 2 responsive checks passed 7/7 in both. The first package I02 attempt timed out waiting 30 seconds for the authenticated site selector; the same package passed on a separate repeat. No confirmed root cause is claimed; both logs are retained.

An API image container on the Keycloak fixture Compose network could not reach `https://localhost:44739` (ECONNREFUSED), because localhost is the API container. Therefore actual container-to-Keycloak login, signature verification and signing-key refresh have not passed and prevent development acceptance. Set up a stable mutually resolvable issuer hostname and port with a matching trusted certificate and run these tests in the container without bypassing TLS/issuer checks. Key backup, wrong/missing key and version tests use only random fictional keys. Multi-version key rotation and an actual secret-store backup/restore rehearsal remain production blockers; see the backend `RECOVERY_KEY_OPERATIONS.md`.
